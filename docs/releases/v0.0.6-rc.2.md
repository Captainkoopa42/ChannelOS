# ChannelOS 0.0.6 — Windows release candidate 2

This candidate retains Broadcaster/Studio, complete ads, portable setups,
watch-ahead playback and simple ad controls from the latest 0.0.5 source lineage.

Fixed Library additions losing settings, stuck numeric channel entry and delayed
retuning, unavailable-source startup, incomplete source dependency checks,
delete/recreate state inheritance, ignored Advanced overrides, stale calendar
snapshots after swaps, ad queue repeats after insertion, and abandoned future ads
entering the airing ledger. The final audit also repaired partial-source program
clock reuse, QML page-notification routing, source dependency query scaling,
Studio controls overflowing smaller supported windows, and Ad Bin dialog sizing.

Candidate 2 also checkpoints real ad viewing before channel mutations. Deleting
a playing station archives its final coverage safely; a refused deletion restores
the decoder. Draft edits validate against that saved viewing evidence.

Download `ChannelOS-0.0.6-windows-x64.zip` and `SHA256SUMS.txt` from this release.
Extract the whole folder and run `ChannelOS.exe`. Python, Qt and VLC are included.
Source and package revision are recorded in `PACKAGE-BOM.json`.

The publication workflow requires the Python 3.11/3.12/3.13 and QML suites, locked
Windows packaging, native bundled VLC transition smoke tests, and packaged portable
relocation/startup checks on the candidate commit.

Existing runtime schema 2 receives a backup before schema-3 migration. Keep a full
copy of an existing setup for upgrade testing. For build rollback, restore the
matching pre-upgrade setup backup; 0.0.5 must not open the schema-3 runtime.
Channel schemas 0.1–0.6 remain supported. Media files remain under your control.

Physical speaker/headphone switching, real controller hot-plug and a physical USB
move still require device acceptance. Follow `docs/releases/WINDOWS_0.0.6_ACCEPTANCE.md`.
This prerelease is supplied for that testing; it does not claim those checks passed.
