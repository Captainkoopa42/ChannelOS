# ChannelOS 0.0.6 — Windows performance candidate 3

This test candidate retains candidate 2's release repairs and improves all six
reported heavy actions: opening Channels, creating and deleting a channel,
clearing a draft, adding a large schedule, and starting the application.

Channels now reuses parsed definitions and no longer rebuilds Library cards.
Channel saves and deletions prepare in the background with progress, cancellation
before commit, a final viewing checkpoint, stale-input checks, and rollback.
Unchanged stations retain their runtimes, playback decoder, and paused position.
Channel history archival uses bounded database operations and remains restorable.

Studio publishes bulk changes once, indexes source membership, shares its visible
schedule rows, prepares Auto Fill results away from the interface, and loads
inactive calendar views only when needed. Fixed start times and the 10,000-block
limit remain enforced.

Startup shows an early window, prepares the saved station first, then loads the
Library and remaining stations. Guide projections load around the selected row;
management screens are created on their first visit. Offline media remains
manageable without deleting its identity or watch history.

Extract the entire `ChannelOS-0.0.6-windows-x64.zip` folder and run `ChannelOS.exe`.
Python, Qt, and VLC are included. The matching commit is recorded in
`PACKAGE-BOM.json`; verify the ZIP against `SHA256SUMS.txt`.

Publication requires the Python 3.11/3.12/3.13 and QML suites, locked Windows
packaging, native VLC cut/fade/hold checks, a real staged Qt startup/saved playback
check, and the packaged portable relocation checks on this exact commit.

Keep a complete copy of your setup for upgrade testing. Existing schema-2 runtime
databases receive a backup before schema-3 migration; older builds must not open
schema-3 data. To roll back, restore the matching complete pre-upgrade setup.

Measured development fixtures are not a timing guarantee for your PC, network,
or USB drive. Physical audio-device switching, controller hot-plug, a real USB
move, and prolonged playback still need device acceptance using
`docs/releases/WINDOWS_0.0.6_ACCEPTANCE.md`.
