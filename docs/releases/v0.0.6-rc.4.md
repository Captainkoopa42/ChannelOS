# ChannelOS 0.0.6 — Windows performance candidate 4

This Windows test candidate includes the first performance pass and completes the
seven additional areas identified in the remaining-system audit.

- Library keeps its sorted source/search data, defers hidden views, and updates
  artwork and watch progress by asset ID. Returning to an unchanged Library
  reuses the existing projection. The selected item's info panel stays current.
- Playback uses indexed time ranges and pending-airing records instead of
  decoding accumulated ad history on every refresh. Forecasting never counts
  as actual viewing. Canonical plans and aired/viewed ledgers remain intact.
  Changes, imports, retirement, and restores invalidate derived data safely
  across database connections.
- Volume and mute no longer inspect the thumbnail directory. Artwork cache
  accounting is maintained incrementally; cache clearing and limit pruning run
  away from the interface. Queued requests from closed Library views are skipped.
- Unchanged rescans share a private database connection and commit bounded
  metadata batches. Source confirmation is a cancellable, read-only background
  check. The scan still reconciles removals only after successful completion.
  Files changed during hashing/probing are rejected without trusting a mismatched
  identity or fingerprint.
- Portable review and setup preparation run in workers. Copy Setup reuses the
  reviewed plan, checks for changed setup input, checkpoints current viewing,
  and pins consistent database snapshots before the worker converts/copies them.
  Existing media, history, cancellation, and atomic publication rules remain.
- Ad selection indexes source membership and canonical asset exclusions, keeps
  natural clip/source order, and updates counts without regrouping every clip.
- Missing/reconnected media recovery prepares replacements in the background,
  rejects stale results, and adopts only changed channels in small Qt batches.
  Unaffected playback sessions, Viewer Clocks, and Guide rows remain in place.

The channel-update overlay also prevents keyboard input from editing controls
behind it while retaining keyboard/controller cancellation before commit.

Extract the entire `ChannelOS-0.0.6-windows-x64.zip` folder and run `ChannelOS.exe`.
Python, Qt, and VLC are included. The source commit is recorded in
`PACKAGE-BOM.json`; verify the ZIP against the accompanying `SHA256SUMS.txt`.
Candidate 3 remains available under its own immutable tag.

Publication requires the full Python 3.11/3.12/3.13 and QML suites, locked Windows
packaging, native VLC cut/fade/hold checks, staged Qt startup/saved playback, and
packaged portable relocation checks on the exact candidate commit.

Generated scale-fixture measurements and work bounds are recorded in
`docs/performance/windows-background-work-2026-11-03.json`. These observations
are not timing guarantees for another PC, network, or drive.

Keep a complete copy of your setup for upgrade testing. Runtime/index schema 3
and portable format 1 are unchanged by this pass; the new history indexes are
recoverable derivatives of the canonical tables. Older builds must not open
schema-3 data. Restore a matching complete pre-upgrade setup when rolling back.
Physical audio-device switching, controller hot-plug, a real USB move, and
prolonged playback still need device acceptance using
`docs/releases/WINDOWS_0.0.6_ACCEPTANCE.md`.
